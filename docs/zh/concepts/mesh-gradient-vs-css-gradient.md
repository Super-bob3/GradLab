# 网格渐变 vs CSS 渐变

网格渐变和 CSS 渐变都能产生颜色过渡，但视觉效果和技术权衡截然不同。以下是直接对比。

## CSS 渐变能做什么

CSS 渐变（`linear-gradient`、`radial-gradient`、`conic-gradient`）是浏览器原生支持的。无需 JavaScript，即时加载，兼容所有浏览器。

```css
background: linear-gradient(135deg, #667eea 0%, #764ba2 100%);
```

CSS 渐变非常适合：
- 细微的色调和叠加效果
- 简单的方向性色彩填充
- 边框、按钮和 UI 装饰
- 需要保证性能且零依赖的场景

## CSS 渐变的局限

CSS 渐变受限于单轴插值。线性渐变只能沿直线流动；径向渐变只能从一个点辐射。虽然可以叠加多个带透明度的渐变来模拟复杂效果，但结果往往看起来是人工拼凑的，而非自然的。

复杂 CSS 渐变常见的问题：
- **灰色泥团** — 在 RGB 中混合互补色会产生暗淡、不饱和的中间色
- **色带** — 色标不足时出现明显的色彩分界
- **几何感** — 渐变看起来像设计工件而非有机光线

## 网格渐变增加了什么

网格渐变将颜色分布在二维平面的多个节点上，混合时同时考虑所有相邻节点的关系，产生：

- **深度感** — 颜色似乎从表面浮现和消退
- **有机流动** — 过渡看起来像光线，而非数学计算
- **丰富的颜色交互** — 三到四种颜色可产生数十种可见的中间色调

动画时，网格渐变的生动感是 CSS 渐变无法通过再复杂的关键帧链条来复现的。

## 视觉对比

| 特质 | CSS 渐变 | 网格渐变 |
|------|---------|---------|
| 颜色过渡 | 线性、几何 | 有机、多方向 |
| 混合丰富度 | 低—中 | 高 |
| 动画感受 | 机械 | 流体 |
| 唯一性 | 易于复制 | 视觉独特 |
| 复杂度 | 简单 | 复杂 |

## 技术对比

| 因素 | CSS 渐变 | 网格渐变 |
|------|---------|---------|
| 浏览器支持 | 通用 | 需要 WebGL |
| 性能 | 零开销 | GPU 加速 |
| 文件体积 | ~100 字节 | HTML ~200 KB |
| 动画 | CSS 过渡 | 实时着色器 |
| 代码可编辑性 | 是 | 需要生成器 |

## 何时使用 CSS 渐变

- UI 微元素：按钮、徽章、边框
- 加载速度关键且不需要动画的背景
- 无法保证 WebGL 支持的项目（如邮件客户端、部分嵌入式浏览器）
- 简单的双色方向性填充

## 何时使用网格渐变

- Hero 区和落地页——视觉冲击力至关重要的场景
- 需要有生命感但又不想用视频的动态背景
- 品牌资产——社交图形、演示文稿、壁纸
- 任何希望背景成为设计亮点而非中性填充的场景

## 两者结合使用

两种方案并不互斥。常见模式：用网格渐变生成器导出的 PNG 作为 CSS `background-image`，兼顾网格渐变的视觉丰富度与 CSS 属性的简洁性，代价是失去动画效果。

```css
.hero {
  background-image: url('gradient.png');
  background-size: cover;
}
```

需要动画版本时，用 `<iframe>` 引用导出的 HTML，或用 `<video>` 引用导出的 MP4。
